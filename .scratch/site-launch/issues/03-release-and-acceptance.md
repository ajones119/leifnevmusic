# Set release constraints and specification acceptance

Type: grilling
Label: wayfinder:grilling
Status: open
Blocked by: none

## Question

Confirm Astro static output on Render, deadline, recurring-cost ceiling, analytics needs, target search identity, domain readiness, and how visual quality will be approved before release. Define measurable mobile, accessibility, performance, SEO, and content-readiness acceptance criteria.

## Comments

- Mobile use is expected to dominate. UI taste is very important; SEO is moderately important.
- Public identity proposed by user: Leif Nevener, musician in Oklahoma City.
- User accepted the proposed Astro/Render/GitHub workflow, free initial hosting without analytics or paid services, and content/accessibility/mobile visual launch gates. No fixed deadline was provided.
- User subsequently specified an approximately 800px maximum centered column for desktop. Mobile is the primary pass; desktop polish follows later, while baseline wide-screen usability remains required.
- These accepted constraints and proposed measurable checks are consolidated in [the specification](../spec.md); remaining review is part of specification acceptance.
